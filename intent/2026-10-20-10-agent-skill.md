# Intent: agent skill for the Craft apps, and a compact pdfcraft MCP default

## Problem

The modules configure all thirteen MCP servers, but agents still lack
three things (#10):

1. **The servers can't explain how they relate to the GUI.** Each server
   sends 400–1300 characters of instructions about its own tools. None of
   them says how to drive a running app:
   - `<app> --control PORT` plus `<app>-cli mcp --connect/--bridge/--attach`,
     with a different flag per app;
   - read/write roots;
   - soundcraft's seven desktop-only tools;
   - why vectorcraft needs `--headless`.
   Upstream ships no user-facing skill. Its AGENTS.md and CLAUDE.md files
   are for app developers.
2. **pdfcraft floods the context.** Its server lists 163 tools (about
   154 KB). With `--compact` it lists 17 plus `tool_search`/`tool_call`
   (about 13 KB), still reaching all of them. Measured on 2026-10-20.
3. **Users of other agents miss a step.** Codex, opencode, Crush and the
   rest get these servers only if they turn on
   `programs.<agent>.enableMcpIntegration` in Home Manager. The README
   doesn't say so.

## Proposed outcome

- An opt-in option, for example `programs.craftapps.skill.enable`, that
  installs one hand-written `craftapps` skill for every agent Home
  Manager supports with a `skills` option (claude-code, codex, opencode,
  crush, copilot-cli, antigravity-cli). It covers the installed apps, how
  to choose headless or bridge mode, the exact flags per app, roots, and
  the desktop-only tools.
- The pdfcraft MCP server starts with `--compact` by default, overridable
  through `apps.pdfcraft.mcp.args` like any other app.
- The README tells users how to switch on MCP for their agent and how to
  check it with `claude mcp list`.

## Affected users and systems

- This flake: `modules/common.nix` (`mcpArgs`, new option),
  `modules/home-manager.nix`, `modules/nixos.nix` (shared module), the
  checks in `flake.nix`, the skill text, README, llms.txt and AGENTS.md.
- p620 and razer after a lock bump: pdfcraft's MCP entry gains
  `--compact`. The skill appears only if nixos-config enables it.

## Constraints

- No service or daemon: the servers stay stdio and on demand.
- No skills generated from `<app>-cli commands --json`. At 79–352 KB they
  are too big and would go stale with every daily update.
- The skill states only facts verified against the installed CLIs, and
  stays small: one file, not thirteen.
- The skill only installs where Home Manager's `programs.<agent>.skills`
  exists, guarded like `programs.mcp` today. Older Home Manager versions
  must still evaluate.
- Never write `/etc/claude-code/managed-mcp.json`. No `hardware.*`.

## Open questions

- Should the skill be opt-in (off by default, as proposed) or on by
  default whenever `mcp.enable` is on?
