# Intent: package FigCraft as the 13th Craft app

## Problem

storytold publishes a 13th app, FigCraft (the ArtCraft take on Figma), at
`storytold/figcraft`. This flake packages only twelve, so FigCraft users get
no package, no `programs.craftapps.apps.figcraft` switch, no MCP server
entry and no daily updates (#6).

## Proposed outcome

- `nix build .#figcraft` works on x86_64 and aarch64 Linux, and `default`
  includes it.
- `programs.craftapps.apps.figcraft.enable` exists in the NixOS and Home
  Manager modules and follows `enableAll` like the others.
- With `mcp.enable`, FigCraft's built-in MCP server (`figcraft-cli mcp`) is
  configured like the other apps, if it answers headless.
- The daily update workflow keeps FigCraft current.
- README, llms.txt and AGENTS.md say thirteen apps and list FigCraft.

## Affected users and systems

- This flake: `scripts/update.py` (APPS table), `apps.json` (written by the
  updater), docs.
- Every consumer with `enableAll = true`, including the user's nixos-config
  on p620 and razer: FigCraft installs on their next lock bump, and with
  `mcp.enable` a `figcraft` server is added to `~/.claude.json`.

## Constraints

- Follow AGENTS.md "Adding a new Craft app": the `apps.json` entry comes
  from `update.py`, never by hand.
- One generic builder: no FigCraft branch in `package.nix`. The v0.7.0
  tarball has the same layout as the others (`bin/figcraft`,
  `bin/figcraft-cli`, `share/{applications,icons,metainfo,doc}`), checked
  on 2026-10-20.
- Both architectures: v0.7.0 ships x86_64 and aarch64 tarballs.
- CI must pass on both architectures before merge.
- The modules must not set any `hardware.*` option.
