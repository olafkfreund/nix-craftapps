# Plan: agent skill for the Craft apps, and a compact pdfcraft MCP default

Approved decisions, carried over from the spec:

- pdfcraft's MCP server defaults to `--compact` through `mcpArgs` in
  `modules/common.nix`. The full list is 163 tools (about 154 KB);
  compact gives 17 plus `tool_search`/`tool_call`, measured on 2026-10-20
  with pdfcraft 0.9.0. Users can override `apps.pdfcraft.mcp.args`.
- One hand-written skill, `skills/craftapps/SKILL.md`, under about 150
  lines, with frontmatter `name: craftapps` and a triggering
  `description`. It covers the 13 apps, headless first, bridge mode with
  the per-app flag, roots, soundcraft's desktop-only tools, vectorcraft's
  `--headless`, pdfcraft's `--compact` with `tool_search`, and never
  running a GUI with `--help`. No version numbers and no command lists.
- New option `programs.craftapps.skill.enable` (mkEnableOption, **off by
  default**, independent of `mcp.enable`).
- When on, `programs.<agent>.skills.craftapps = <SKILL.md path>` is set for
  each of claude-code, codex, opencode, crush, github-copilot-cli and
  antigravity-cli, but only where `options.programs.<agent> ? skills`
  exists. Older Home Manager versions must still evaluate. An attribute is
  added (merging with the user's attrset), never a directory path.
- The NixOS module adds the same wiring to `home-manager.sharedModules`.
- Docs: README (option row; MCP section: `enableMcpIntegration` for other
  agents, `claude mcp list`, `--compact` and how to undo it, the
  path-valued `skills` conflict), llms.txt, AGENTS.md (layout row, MCP
  trap, an "Adding a new Craft app" step).
- Known limit: a user whose `programs.<agent>.skills` is a path gets
  "conflicting definitions" when the option is on. Document it; don't
  work around it.

2. New `modules/skill.nix`: a Home Manager module factory shared by both
   modules:

   ```nix
   # Installs the craftapps skill for each agent whose Home Manager module has `skills`.
   isEnabled:
   { config, options, lib, ... }:
   let
     agents = [ "claude-code" "codex" "opencode" "crush" "github-copilot-cli" "antigravity-cli" ];
     present = builtins.filter (a: options.programs ? ${a} && options.programs.${a} ? skills) agents;
   in
   {
     config = lib.mkIf (isEnabled config) {
       programs = lib.genAttrs present (_: { skills.craftapps = ../skills/craftapps/SKILL.md; });
     };
   }
   ```

   If `lib.mkIf` over `programs` with option-derived keys recurses, move
   the filter so the keys come only from `options`. This is the same
   class of trap as the comment in `modules/nixos.nix:72`. If it still
   fails, fall back to `lib.optionalAttrs` per agent under `config`,
   exactly like that comment.
   → verify in step 4's checks.
   Traps: no `options.programs` access at the module's top level outside
   `config`; it recurses.

## Rollback

Revert the commit. pdfcraft returns to its full tool list after the next
rebuild. Users who turned on `skill.enable` must remove that line, or
evaluation fails on the missing option.
