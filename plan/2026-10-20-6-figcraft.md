# Plan: package FigCraft as the 13th Craft app

Approved decisions, carried over from the spec:

- FigCraft (`storytold/figcraft`, v0.7.0) has the same tarball layout as the
  other apps: `bin/figcraft`, `bin/figcraft-cli`, `share/...`. No change to
  `package.nix`, `default.nix`, the modules or `flake.nix` code. They all
  iterate over `apps.json`, and the checks count from it.
- The `apps.json` entry is written only by `scripts/update.py`. Never edit
  versions or hashes by hand.
- The MCP server is headless by default (`figcraft-cli mcp` answered
  `initialize` on 2026-10-20), so there is no `mcpArgs` entry in
  `modules/common.nix`.
- The docs say thirteen apps and list FigCraft as "Figma", "Interface design
  and prototyping".
- PR #7 is already merged and this branch is rebased on it (`b6801fe`), so
  the updater runs on current versions.

## Steps

1. `scripts/update.py:23`: after the `"filmcraft"` row in `APPS`, add
   `"figcraft": ("FigCraft", "Figma-style interface design and prototyping"),`.
   → verify by `python3 scripts/update.py --self-test` printing `self-test ok`.
   Traps: stdlib only; keep the alphabetical order of the table.

2. `apps.json`: run `python3 scripts/update.py figcraft`. It downloads both
   tarballs and prefetches the hashes.
   → verify by
   `jq '.figcraft | {version, tag, repo, desktopId, s: (.sources|keys)}' apps.json`
   showing 0.7.0, v0.7.0, `storytold/figcraft`, `ai.storyteller.figcraft`
   and both `aarch64-linux` and `x86_64-linux`. `git diff apps.json` must
   only add the figcraft key; the other twelve entries are untouched.
   Traps: never hand-edit `apps.json`. If the updater refuses for a missing
   architecture, stop and report rather than relaxing it.

   - `nix build .#figcraft -L`: the log shows autoPatchelf with

before merge.

## Rollback

Revert the merge commit. Consumers lose `figcraft` on their next lock
bump. With `mcp.enable`, a stale `figcraft` entry stays in `~/.claude.json`
until `claude mcp remove figcraft` is run.
