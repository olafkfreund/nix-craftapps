# Spec: package FigCraft as the 13th Craft app

## Design

FigCraft fits the existing data-driven design, so it is a data change plus
docs. No Nix code changes.

1. **`scripts/update.py`**: add one row to `APPS`, in alphabetical order
   after `filmcraft`:
   `"figcraft": ("FigCraft", "Figma-style interface design and prototyping")`.
   The daily workflow then keeps it current with no other change.
2. **`apps.json`**: written by `python3 scripts/update.py figcraft`, never by
   hand. Expected entry: version 0.7.0, tag v0.7.0, `repo`
   `storytold/figcraft`, `desktopId` `ai.storyteller.figcraft`, x86_64 and
   aarch64 sources. The desktop ID matches the tarball's
   `share/metainfo/ai.storyteller.figcraft.metainfo.xml`.
3. **Package, modules, MCP**: nothing to edit. `default.nix`, both modules
   and `mcp.servers` iterate over `apps.json`, and the flake checks count
   from it (`builtins.length names`). FigCraft's MCP server is headless by
   default, so it gets no `mcpArgs` entry. This was checked on 2026-10-20:
   the unpatched v0.7.0 `figcraft-cli mcp` answered `initialize` with
   `"result"` and reported "headless (in-process engine session; no
   window)".
4. **Docs**: change "twelve"/"12" to "thirteen"/"13" and add a FigCraft row
   to the app tables, in:
   - `README.md` (lines 5, 7, 74, 456 and the app table);
   - `llms.txt` (line 3 and the app list);
   - `AGENTS.md` (lines 8, 13, 36, and "When storytold publishes a 13th
     app" becomes "a 14th app");
   - `flake.nix` (the `description`, line 2);
   - `docs/GPU.md` (line 56).
   If `strings` on the binary shows its own `*_GPU*` switches, note them in
   `docs/GPU.md`, per AGENTS.md step 5.
5. **Ordering with PR #7**: the open update PR rewrites `apps.json`. Merge
   #7 first, then rebase this branch and run the updater, so the FigCraft
   entry lands on top of current versions with no hand-merged JSON.

## Alternatives rejected

- **Hand-writing the `apps.json` entry**: forbidden by AGENTS.md, and the
  hash must come from the real download.
- **Adding FigCraft to the module defaults only**: there is no
  module-level app list to change. Everything follows `apps.json`.
- **Waiting for the daily workflow to pick it up**: `update.py` only
  refreshes apps in `APPS`, so it never discovers a new repo on its own.

## Risks

- **Missing runtime library for the GUI**: autoPatchelf can pass while the
  GUI `dlopen()`s something absent (AGENTS.md trap). A manual GUI launch
  covers this. On p620, Xwayland is still broken from the earlier session,
  so the launch must use a working Wayland/X session or `WINIT_UNIX_BACKEND`
  as the other apps do.
- **Consumers with `enableAll = true`** (p620, razer) get one more package,
  about the size of the other apps, and one more MCP server entry in
  `~/.claude.json` on their next lock bump. This is the intended outcome.
- **Fonts**: FigCraft indexes installed fonts unless `--no-system-fonts` is
  set. The existing `linkFonts` covers `/usr/share/fonts` on NixOS.

## Verification

- `python3 scripts/update.py --self-test` passes.
- `nix build .#figcraft`: autoPatchelf reports `0 dependencies could not be
  satisfied`, and `result/bin/figcraft-cli --version` prints
  `figcraft-cli 0.7.0`.
- `nix flake check -L` passes. That covers the `cli` and `mcp` checks for
  13 apps, and the module checks, whose counts follow `apps.json`.
- `timeout 8 ./result/bin/figcraft` exits 124 (stayed up) on a working
  display session.
- CI passes on x86_64 and aarch64 before merge.
