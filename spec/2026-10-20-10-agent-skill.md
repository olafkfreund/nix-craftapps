# Spec: agent skill for the Craft apps, and a compact pdfcraft MCP default

The intent was approved as written, so the skill is **opt-in** (off by
default).

## Design

### 1. pdfcraft `--compact` by default

`modules/common.nix`: add `pdfcraft = [ "--compact" ];` to `mcpArgs`, with
a one-line why comment: the full list is 163 tools (about 154 KB), and
`--compact` lists 17 plus `tool_search`/`tool_call`, which still reach
every tool. This was measured on 2026-10-20 with pdfcraft 0.9.0. The
default of `apps.pdfcraft.mcp.args` becomes `[ "mcp" "--compact" ]`, and
users can override it like any other app. The existing `mcp` check already
runs each server with its module args, so it tests `--compact`.

### 2. One hand-written skill: `skills/craftapps/SKILL.md`

A new file in the repo, under about 150 lines, with Claude-style
frontmatter (`name: craftapps`, a `description` that triggers on the app
names and on "drive the running app"). Its contents:

- **What the apps are:** the thirteen apps, one line each, with the
  familiar app each one replaces.
- **Headless first:** every server starts its own in-process session.
  Use it for files, and save explicitly.
- **Driving the open window (bridge mode):** start the GUI with
  `<app> --control PORT`, then point the server at it. The flag is
  per app:
  - `--connect`: cadcraft, deckcraft, designcraft, gridcraft, lightcraft,
    soundcraft, vectorcraft, wordcraft;
  - `--bridge`: effectcraft, filmcraft, photocraft;
  - `--attach PORT`: figcraft;
  - pdfcraft drives its GUI with `pdfcraft-cli ui --control FILE`.
  Each of these is re-verified against the installed `<app>-cli` usage
  text before it is written down.
- **Gotchas:**
  - read/write roots (`--automation-read-root`/`-write-root`; pdfcraft
    uses `--root`) cannot be combined with bridge mode;
  - soundcraft's seven desktop-only tools;
  - vectorcraft runs with `--headless` because its default is bridge mode;
  - pdfcraft runs with `--compact`, so use `tool_search` to find a tool;
  - never run a GUI with `--help`, because it opens a window.
- **Finding commands:** `list_commands`/`command_list` and
  `<app>-cli commands --json` give the full set; the skill doesn't copy
  them.

It contains no version numbers or command lists, so it does not go stale
with the daily updates.

### 3. The option and its wiring

- `modules/common.nix`: `skill.enable = lib.mkEnableOption "the craftapps
  agent skill for every Home Manager agent with a skills option"`. It
  does not depend on `mcp.enable`, though it is mostly useful with it.
- `modules/home-manager.nix`: when `cfg.skill.enable`, for each of
  `claude-code`, `codex`, `opencode`, `crush`, `github-copilot-cli` and
  `antigravity-cli`, set `programs.<agent>.skills.craftapps =
  ../skills/craftapps/SKILL.md`. Only agents where
  `options.programs.<agent> ? skills` exists are set, guarded with
  `lib.optionalAttrs` at the top of `config` exactly like `programs.mcp`,
  so older Home Manager versions still evaluate. A file path makes each
  of these modules write `skills/craftapps/SKILL.md` in that agent's
  directory. Home Manager writes nothing for agents that are not enabled.
- `modules/nixos.nix`: the existing `home-manager.sharedModules` entry
  gains the same skill wiring when `cfg.skill.enable`, so NixOS users get
  it for every Home Manager user, as with MCP.

### 4. Docs

- README: an option row for `skill.enable`. In the "MCP servers" section:
  - for agents other than Claude Code, set
    `programs.<agent>.enableMcpIntegration = true;`;
  - check the servers with `claude mcp list`;
  - the pdfcraft `--compact` default, and how to undo it.
- `llms.txt`: one line each for the skill option and `--compact`.
- `AGENTS.md`:
  - a layout row for `skills/`;
  - the MCP trap gains "pdfcraft defaults to `--compact`";
  - a step in "Adding a new Craft app": add the app to
    `skills/craftapps/SKILL.md`.

## Alternatives rejected

- **Thirteen per-app skills**: they would repeat each server's own
  instructions. One file is enough to explain bridge mode and the gotchas.
- **Generating from `commands --json`**: 79–352 KB per app, and stale
  after every update.
- **Vendoring upstream AGENTS.md/CLAUDE.md**: those are for app
  developers.
- **On by default**: you approved opt-in.
- **Writing `~/.claude/skills` with `home.file`**: this would bypass each
  agent module and cover only one agent. The `skills` options cover six.
- **Setting `skills` to a directory path**: that replaces a user's own
  attrset of skills. Adding one attribute merges with them instead.

## Risks

- **A user who sets `programs.<agent>.skills` to a path** (a whole skills
  directory) gets a type conflict ("conflicting definitions") when
  `skill.enable` is on, because the option is either an attrset or a path.
  It only affects people who opt in. The README states it, and the
  workaround is to add the file to their directory themselves.
- **Bridge flags change upstream.** The skill names flags, not versions.
  A wrong flag leads the agent to a usage error, not silent damage.
  AGENTS.md's "Adding a new Craft app" covers new apps, but not flag
  changes in existing apps.
- **`--compact` hides tools from clients without tool search.** They can
  still use `tool_search`/`tool_call`, and the default can be overridden.
- **p620 and razer:** after a lock bump, pdfcraft's entry in
  `~/.claude.json` gains `--compact` through the existing reconcile. The
  skill only appears if nixos-config sets `skill.enable`, which is not
  part of this issue.

## Verification

- `module` check: `/etc/craftapps/mcp.json` has pdfcraft args
  `["mcp","--compact"]`.
- `hm-module` check, with a stub `programs.claude-code.skills` option
  shaped like Home Manager's:
  - `skill.enable = true` sets `skills.craftapps`, and the shared module
    sets it too;
  - `skill.enable = false` leaves `skills` empty;
  - a configuration without any `programs.<agent>` options still
    evaluates.
- An eval against the real Home Manager from nixos-config's lock:
  `programs.claude-code.skills.craftapps` is set, and the generated
  `home.file` contains `.claude/skills/craftapps/SKILL.md`.
- The `mcp` check passes, so pdfcraft answers `initialize` with
  `--compact`.
- Every bridge flag in `SKILL.md` matches the `<app>-cli` usage text of the
  installed version.
- `nix flake check`, the updater's `--self-test` and `nix fmt` are clean.
  CI passes on both architectures.
